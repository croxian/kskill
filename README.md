# 영화관 빈좌석 알리미

특정 상영관·영화·시간대를 동시에 감시하다가, 지정한 좌석 블록에서 단석 또는 연석이
열리면 알리고, 공식 예매 화면에서 좌석을 확보한 뒤 **결제 직전에 멈추는** 도구.

본인 관람용 개인 도구다. 좌석을 쌓아두거나 되파는 용도가 아니다.

`loop.ts` 는 조회·좌석맵·알림·시계를 전부 주입받으므로 실제 폴링 없이 테스트된다.

## 감시 스펙

축을 배열로 두고 **축 사이는 AND, 배열 안은 OR**. 조합 폭발 없이 멀티 체크가 된다.

```ts
{
  theaters: [{ chain: 'lotte', theaterId: '1016' }, ...],
  movies:   ['24128'],                       // 비우면 전 상영작
  dates:    ['20260809'],
  windows:  [{ from: '17:00', to: '21:00' }, { from: '21:00', to: '26:00' }],
  screens:  ['101609'],                      // 비우면 전 상영관
  block:    { kind: 'ratio', rowPct: [0.4, 0.8], colPct: [0.3, 0.7] },
  party:    { mode: 'adjacent', size: 2 },
  action:   'hold',
  pollFloorSec: 30,
  expiresAt: '2026-08-09T18:30:00+09:00',
}
```

시간대는 24 를 넘는 표기를 그대로 받는다. 롯데 실측에 `24:35` 시작,
`25:42` 종료 회차가 있다 — `{ from: '21:00', to: '26:00' }` 로 심야를 잡는다.

## 폴링

```
3일 초과   30분   취소가 드물고 나도 급하지 않다
1~3일      10분   일정 변경 취소가 시작된다
3~24시간    3분   취소 밀도가 가장 높은 구간
30분~3시간 45초   노쇼 취소와 결제 실패 좌석이 풀린다
30분 미만  중단   현장 발권이 더 빠르다
```

간격에 흔들림을 줘 정각 동시요청을 피한다. **하한 30초는 어떤 경우에도 깨지 않는다.**
간격을 줄여도 취소표를 더 잡지는 못한다 — 취소는 초 단위로 쏟아지지 않는다.
확률을 올리려면 감시 대상 회차 수를 늘려야 한다.

폴링 1회당 요청 수 = **지점 수 × 날짜 수**. 영화를 몇 편 걸든 늘지 않는다.

조회가 **전부** 실패한 것과 감시할 회차가 없는 것은 구분한다. 둘 다 목록이 비지만,
전자에서 감시를 끝내면 잠깐의 네트워크 장애로 조용히 죽는다.

## 알림

```
🎟 빈 좌석 발견

오디세이
월드타워 · 9관
8월 9일(일) 19:10

좌석 J10, J11 · 2연석
이 회차 잔여 6석

            SCREEN
-------------------------------
A                        # ####
B   ## #### ############## ####
C   ## #### ######.####### ####
...
H   #. .### ############## ####
I   ## #### ############## ####
J   ## #### #OO########### ####
```

`.` 빈자리 · `#` 판매됨 · `x` 남이 선점 중 · `O` 후보 · 통로는 빈 칸.

`x` 가 많으면 그 회차는 경쟁이 붙은 것이다. 알림 본문에도 `선점 중 N석` 으로 나온다.

원래 좌석맵을 SVG 로 붙일 생각이었는데, 텔레그램은 사진으로 SVG 를 받지 않고
(JPEG/PNG/GIF 만) 래스터라이저를 끌어오면 의존성이 무거워진다. 고정폭 코드 블록이면
의존성 0 에 모바일에서도 인라인으로 뜬다. H 행을 보면 `#. .###` — 통로 공백이
H04 와 H05 를 갈라놓는 게 눈에 보인다.

메시지에는 **딥링크 버튼**이 붙는다. 알림에서 중요한 건 포맷이 아니라 손가락이
움직이는 거리다. 앱을 열어 지점을 찾고 회차를 고르는 30초 동안 자리는 사라진다.

> ⚠️ **롯데에는 회차 단위 딥링크가 없다.** codegen 으로 확인했다 — 예매 전체가
> `/NLCHS` 한 페이지 안의 클릭이라 회차를 주소로 가리킬 수 없다. 알림 버튼은
> 예매 첫 화면으로 보낸다. 다른 체인에 딥링크가 있으면 `LOTTE_DEEPLINK` 템플릿에
> 넣을 수 있게 자리는 남겨 뒀다.

홀드 진행 상황은 **첫 알림 메시지를 고쳐 쓴다**. 남은 시간을 새 메시지로 계속
보내면 도배가 된다.

알림 발송 실패는 감시를 죽이지 않는다. 봇 토큰이 만료돼도 폴링은 계속 돌아야
다음 취소표를 놓치지 않는다.

한 번의 폴링에서 보내는 알림은 `maxAlertsPerRun`(기본 5)까지다. 첫 폴링은 전 회차를
훑으므로 조건이 넓으면 수십 건이 한꺼번에 나가는데, 텔레그램은 같은 대화방에 초당
한 건 남짓만 받아주고 무엇보다 40번 울리는 알림은 아무도 읽지 않는다.
잘린 회차는 좌석맵 조회조차 하지 않는다. 취소표가 잘린 경우에는 **다음 폴링에서
잔여석 변화와 무관하게 다시 확인한다** — 사건을 놓치면 안 되니까.

단, **첫 폴링에서 잘린 것은 넘기지 않는다.** 첫 폴링은 "지금 뭐가 있나"를 한 번
보여주는 목록이지 사건이 아니다. 월드타워 하루치가 111 회차인데 그걸 다 넘기면
시작 시점의 재고가 몇십 분에 걸쳐 찔끔찔끔 알림으로 나온다.

## 설계: 2단 감시

좌석 단위 데이터는 비싸고, 잔여석 카운트는 싸다. 그래서 두 층으로 나눈다.

```
1단  회차별 잔여석 카운트를 주기적으로 폴링
     └ 수가 늘어난 회차 = 취소표 발생 → 2단으로
2단  그 회차만 좌석맵을 1회 조회
     └ 좌석 블록 · 단석/연석 조건을 실제로 판정
```

폴링 1회당 요청 수 = **감시 지점 수**. 영화를 몇 편 걸든 늘지 않는다
(`GetPlaySequence` 가 영화 미지정으로 전 회차를 한 번에 준다).

## 실측으로 확정한 것 — 2026-08-09 롯데시네마 월드타워 9관

전부 실제 예매 화면의 DevTools 캡처와 API 응답 대조로 확인했다. 추측한 값은 없다.

### 1. `BookingSeatCount` 는 이름과 반대로 **잔여석**이다

```
19:10 div100  Total 342  Booking   7   → 사이트 표기 "6 / 342"
22:40 div100  Total 342  Booking 215   → 30분 전 사이트 "237 / 342"
19:10 div960  Total  18  Booking   0   → 프라임타임 리클라이너 매진
```

`Total - Booking` 으로 계산하면 매진 직전인 회차가 "335석 여유"로 보인다.
결정적 근거는 리클라이너다 — "예매된 수"라면 프라임타임에 0석 팔렸다는 뜻이 된다.

`test/parse.test.ts` 가 이 반전을 회귀 테스트로 잠가 두었다.

### 2. `cinemaID` 앞 두 조각은 지점 속성이 아니라 조회 축이다

```
1|0001|1016  → 40 showtimes   (지역 탭: 서울)
2|0960|1016  →  0 showtimes   (지점 객체의 DivisionCode)
```

`GetTicketingPageTOBE` 응답의 지점에 붙어 있는 `DivisionCode|DetailDivisionCode`
를 그대로 쓰면 서버가 **에러 없이 빈 배열**을 준다. `daiso`(k-skill 의
`korean-cinema-search` 가 경유하는 CLI)가 정확히 이 지점에서 틀려서
월드타워 40개 회차 중 0개를 반환했다.

### 3. 좌석 상태는 `SeatStatusCode` 로만 판단한다

```
  0 →   6   free     판매 가능      ← 사이트 "6석 남음" 과 일치
 50 → 335   sold     예매 완료
 20 →   1   held     남이 지금 붙잡고 있음
 28 →  13 ┐
 80 →   3 │ blocked  장애인석 · 거리두기 등 18석
 23 →   2 ┘
           합 360 · BookingSeats 354 = 360 - 6
```

`free` 가 아닌 것을 셋으로 나눈다. 셋 다 지금은 못 사지만 앞날이 다르다 —
`sold` 는 취소가 나야 돌아오고, `held` 는 몇 분 뒤 풀릴 수 있고,
`blocked` 는 영원히 안 열린다.

**코드 20 이 `held` 라는 건 실측으로 확인했다.** 브라우저에서 좌석 하나를
선택하고 결제 화면까지 가자, 밖에서 조회한 그 좌석이 20 초 만에 `0` 에서
`20` 으로 바뀌고 잔여수도 19 → 18 로 줄었다. 360석 표본에서 코드 20 이
단 1석뿐이었던 것도 이걸로 설명된다 — 구조적 좌석 종류가 아니라 그 순간에만
존재하는 상태다.

이 구분이 값을 하는 지점이 둘 있다.

- "팔리지 않았으니 빈자리" 로 처리했다면 **남이 결제 화면에 붙잡고 있는 자리에
  알림을 보냈을 것이다.** 달려가서 클릭해도 안 되는 자리다.
- 뒤집으면 이 감시기는 **남이 결제를 포기한 순간도 잡는다.** `held` 가 `free` 로
  돌아오면 잔여수가 늘고, `risen` 이 그걸 사건으로 본다. 실제 예매 취소보다
  이쪽이 더 자주 나온다.

### 4. 통로는 `SeatColumGroupNo` 가 직접 알려준다

```
H04→H05  gap 583  group 1→2
H08→H09  gap 583  group 2→3
H22→H23  gap 583  group 3→4
정상 간격 283
```

좌표 추정 없이 구획 번호로 확정할 수 있고, x 간격은 교차 검증용으로 쓴다.
번호가 연속이어도 통로 건너면 연석이 아니다 — `test/runs.test.ts` 의 첫 테스트가
이 함정을 지킨다.

임계값은 **행마다** 잡는다. 같은 관의 리클라이너 행은 정상 간격이 470 이라
일반석 통로 폭(583)에 가깝고, 전체 중앙값으로 재면 멀쩡한 연석이 끊긴다.

### 5. 파라미터 이름 함정

```
GetPlaySequence : cinemaID (대문자 D) — "1|0001|1016" 문자열
GetSeats        : cinemaId (소문자 d) — 1016 숫자
```

헷갈리면 에러 없이 빈 응답만 온다. `screenDivisionCode` 는 필터가 아니라서
100 을 보내도 리클라이너까지 전 좌석이 온다.

## 좌석 확보

좌석 점유는 우회가 아니다. 좌석을 고르고 결제 단계로 넘어가면 서버가 그 자리에
임시 잠금을 건다 — 결제가 끝나기 전에 남이 같은 자리를 사면 안 되니까.
**실측으로 확인했다.** 브라우저에서 좌석 하나를 선택하고 결제 화면까지 가자,
밖에서 조회한 그 좌석이 20초 만에 `SeatStatusCode` `0` → `20` 으로 바뀌고
잔여수도 19 → 18 로 줄었다. 우리가 자동화하는 건 **좌석 선택까지**이고,
그 결과로 생기는 잠금을 사람이 결제할 때까지 붙잡아 둘 뿐이다.

### 홀드는 다른 기기로 넘길 수 없다

KTX·SRT 는 결제 전에 **예약번호**가 발급되어 다른 기기에서 이어서 결제할 수 있다.
롯데 영화 예매에는 그런 중간 상태가 없다. `01 상영시간 → 02 인원/좌석 → 03 결제`
는 한 세션 안에서 끊기지 않고 이어지고, 잠금은 그 브라우저의 세션에 묶인다.
폰에서 사이트를 열면 다른 세션이라 그 자리는 그냥 남의 자리다.

현실적인 선택은 셋이다.

| | 방식 | 되는 상황 |
|---|---|---|
| A | 봇이 PC 에서 잡고 **PC 로 가서 결제** | 집·사무실에 있을 때 |
| B | 봇이 PC 에서 잡고 **폰으로 그 PC 를 원격 조작** | 어디서든 |
| C | 잡지 않고 **알림만**, 폰에서 직접 경쟁 | `action: "notify"` |

**B 가 실질적인 답이다.** 코드가 더 필요하지 않다 — PC 에 원격 데스크톱을 켜 두면,
알림을 받고 폰에서 접속해 이미 결제 화면까지 가 있는 브라우저에서 결제만 누르면 된다.
다만 홀드가 5분 안팎이라 **원격 접속이 미리 준비되어 있어야** 한다.

### 준비

```bash
npm run browser   # chromium
npm run login     # 열린 창에서 직접 로그인
npm run record    # 예매 흐름을 녹화해 셀렉터를 얻는다
```

`npm run record` 로 예매 흐름을 녹화해 셀렉터를 얻었다. 확인된 것:

```
예매        getByRole('link', { name: '예매', exact: true })
지점        locator('#mCSB_1_container').getByRole('link', { name: 지점명 })
영화        getByRole('link', { name: /제목/ })          ← 관람등급이 앞에 붙는다
날짜        getByRole('link', { name: /^11 / })          ← "11 화"
회차        getByRole('button', { name: /상영시간 17:20/ })
좌석 단계   getByRole('link', { name: '인원/좌석 선택' })
인원        locator('#person_10').getByRole('button', { name: '증가' })
좌석        ← 아직 실측 전
결제하기    getByRole('link', { name: '결제하기' })
```

회차 버튼의 접근성 이름에는 `잔여석 35 /` 처럼 **변하는 숫자**가 들어간다.
전체 문자열로 맞추면 잔여석이 바뀌는 순간 못 찾는다. 시작 시각으로만 맞춘다.

**좌석 셀렉터만 남았다.** codegen 은 `getByRole('link', { name: '24' }).first()` 를
뱉었는데, 접근성 이름이 좌석 **번호뿐**이라 열이 다른 같은 번호와 구분되지 않는다.
`.first()` 로 넘기면 엉뚱한 열을 클릭한다 — 조용히 틀리는 종류다.
좌석 `<a>` 의 실제 속성을 보고 `LOTTE_FLOW.seat` 을 채워야 한다.

실측 전에는 `action: "hold"` 로 시작하면 **거부한다.** 추측 셀렉터로 돌리면
조용히 실패해서 왜 안 되는지 알 수 없다.

> 녹화에는 로그인 단계도 찍히지만 **쓰지 않는다.** 아이디·비밀번호를 코드에
> 넣는 순간 캡차와 이상 로그인 탐지에 걸린다. `npm run login` 으로 만든
> `.profile` 세션을 재사용한다.

### 지키는 것

`HoldManager` 가 규칙을 코드로 강제한다. 문서에만 적어두면 아무 의미가 없다.

- **동시 홀드 1건.** 잡는 동안 감시를 멈춘다. 여러 자리를 동시에 막지 않는다
- **미결제 즉시 해제.** 만료를 기다리지 않고, 건너뛰기를 누르면 바로 놓는다
- **재시도 상한.** 같은 회차 3회
- **결제는 사람.** 이 코드에는 결제 버튼을 누르는 경로가 없다
- **캡차·대기열은 중단.** 우회하지 않는다

해제는 브라우저 컨텍스트를 닫는 것으로 한다. 세션이 끊기면 서버가 좌석을 놓는다.
해제가 실패해도 던지지 않는다 — 거기서 던지면 다음 감시가 통째로 막힌다.

## 지켜야 할 선

1. **동시 홀드 1건.** 여러 회차를 동시에 잡아두지 않는다
2. **미결제 즉시 해제.** 만료를 기다리지 않는다
3. **재시도 상한.** 같은 회차 3회, 감시 만료시각 필수
4. **폴링 하한 30초.** k-skill `catchtable-sniper` 규약과 동일
5. **결제는 사람.** 카드 정보 자동 입력·자동 결제 없음

캡차나 대기열이 나오면 우회하지 않고 중단한다.
