# 영화관 빈좌석 알리미

특정 상영관·영화·시간대를 동시에 감시하다가, 지정한 좌석 블록에서 단석 또는 연석이
열리면 알리고, 공식 예매 화면에서 좌석을 확보한 뒤 **결제 직전에 멈추는** 도구.

본인 관람용 개인 도구다. 좌석을 쌓아두거나 되파는 용도가 아니다.

## 지금 상태

| 단계 | 내용 | 상태 |
|---|---|---|
| 0 | 데이터 소스 검증 | ✅ 완료 |
| 1 | 롯데 어댑터 · 좌석맵 파서 | ✅ 완료 |
| 2 | 판정 알고리즘 (블록 · 단석 · 연석) | ✅ 완료 |
| 3 | 감시 루프 (폴링 · diff · 중복 억제) | ✅ 완료 |
| 4 | 텔레그램 알림 | ✅ 완료 |
| 5 | 좌석 확보 (결제 직전 정지) | ⬜ |
| 6 | 메가박스 · CGV 어댑터 | ⬜ |

```bash

cp watch.example.json watch.json
```

## 구조

```
src/types.ts              체인 중립 도메인 모델
src/adapters/lotte/
  api.ts                  엔드포인트·상수 (실측으로 확정한 계약)
  client.ts               HTTP 호출
  parse.ts                원본 응답 → 도메인 모델
src/core/
  spec.ts                 감시 스펙, 시간대·영화·상영관 필터
  block.ts                좌석 블록 지정 (rect · labels · ratio)
  runs.ts                 단석/연석 판정, 후보 점수
  poll.ts                 가변 폴링 간격
  diff.ts                 구역 합치기, 변화 감지, 중복 억제
src/watch/
  loop.ts                 감시 루프 (네트워크·시계 주입)
src/notify/
  telegram.ts             Bot API 클라이언트
  render.ts               알림 본문, 고정폭 좌석 배치도
  deeplink.ts             회차 딥링크
src/main.ts               실행 진입점
```

체인별 차이는 `adapters/` 안에 가둔다. `core/` 는 어느 체인인지 모른 채 동작한다.
`loop.ts` 는 조회·좌석맵·알림·시계를 전부 주입받으므로 실제 폴링 없이 테스트된다.

## 감시 스펙

축을 배열로 두고 **축 사이는 AND, 배열 안은 OR**. 조합 폭발 없이 멀티 체크가 된다.

```ts
{
  theaters: [{ chain: 'lotte', theaterId: '1016' }, ...],
  movies:   ['24128'],                       // 비우면 전 상영작
  dates:    ['20260809'],
  windows:  [{ from: '17:00', to: '21:00' }, { from: '21:00', to: '26:00' }],
  screens:  ['101609'],                      // 비우면 전 상영관
  block:    { kind: 'ratio', rowPct: [0.4, 0.8], colPct: [0.3, 0.7] },
  party:    { mode: 'adjacent', size: 2 },
  action:   'hold',
  pollFloorSec: 30,
  expiresAt: '2026-08-09T18:30:00+09:00',
}
```

시간대는 24 를 넘는 표기를 그대로 받는다. 롯데 실측에 `24:35` 시작,
`25:42` 종료 회차가 있다 — `{ from: '21:00', to: '26:00' }` 로 심야를 잡는다.

## 폴링

```
3일 초과   30분   취소가 드물고 나도 급하지 않다
1~3일      10분   일정 변경 취소가 시작된다
3~24시간    3분   취소 밀도가 가장 높은 구간
30분~3시간 45초   노쇼 취소와 결제 실패 좌석이 풀린다
30분 미만  중단   현장 발권이 더 빠르다
```

간격에 흔들림을 줘 정각 동시요청을 피한다. **하한 30초는 어떤 경우에도 깨지 않는다.**
간격을 줄여도 취소표를 더 잡지는 못한다 — 취소는 초 단위로 쏟아지지 않는다.
확률을 올리려면 감시 대상 회차 수를 늘려야 한다.

폴링 1회당 요청 수 = **지점 수 × 날짜 수**. 영화를 몇 편 걸든 늘지 않는다.

조회가 **전부** 실패한 것과 감시할 회차가 없는 것은 구분한다. 둘 다 목록이 비지만,
전자에서 감시를 끝내면 잠깐의 네트워크 장애로 조용히 죽는다.

## 알림

```
🎟 빈 좌석 발견

오디세이
월드타워 · 9관
8월 9일(일) 19:10

좌석 J10, J11 · 2연석
이 회차 잔여 6석

            SCREEN
-------------------------------
A                        # ####
B   ## #### ############## ####
C   ## #### ######.####### ####
...
H   #. .### ############## ####
I   ## #### ############## ####
J   ## #### #OO########### ####
```

`.` 빈자리 · `#` 판매됨 · `O` 후보 · 통로는 빈 칸.

원래 좌석맵을 SVG 로 붙일 생각이었는데, 텔레그램은 사진으로 SVG 를 받지 않고
(JPEG/PNG/GIF 만) 래스터라이저를 끌어오면 의존성이 무거워진다. 고정폭 코드 블록이면
의존성 0 에 모바일에서도 인라인으로 뜬다. H 행을 보면 `#. .###` — 통로 공백이
H04 와 H05 를 갈라놓는 게 눈에 보인다.

메시지에는 **딥링크 버튼**이 붙는다. 알림에서 중요한 건 포맷이 아니라 손가락이
움직이는 거리다. 앱을 열어 지점을 찾고 회차를 고르는 30초 동안 자리는 사라진다.

> ⚠️ **회차 단위 딥링크는 아직 실측하지 않았다.** 화면 주소라서 XHR 캡처에 잡히지
> 않았다. 예매 화면에서 좌석 선택까지 간 뒤 주소창 URL 을 복사해 `LOTTE_DEEPLINK`
> 템플릿에 넣으면 된다. 비워두면 예매 첫 화면으로 보낸다 — 잘못된 링크보다는 낫다.

홀드 진행 상황은 **첫 알림 메시지를 고쳐 쓴다**. 남은 시간을 새 메시지로 계속
보내면 도배가 된다.

알림 발송 실패는 감시를 죽이지 않는다. 봇 토큰이 만료돼도 폴링은 계속 돌아야
다음 취소표를 놓치지 않는다.

한 번의 폴링에서 보내는 알림은 `maxAlertsPerRun`(기본 5)까지다. 첫 폴링은 전 회차를
훑으므로 조건이 넓으면 수십 건이 한꺼번에 나가는데, 텔레그램은 같은 대화방에 초당
한 건 남짓만 받아주고 무엇보다 40번 울리는 알림은 아무도 읽지 않는다.
잘린 회차는 좌석맵 조회조차 하지 않고, **다음 폴링에서 잔여석 변화와 무관하게
다시 확인한다** — 안 그러면 시작 시점에 이미 비어 있던 자리가 영원히 묻힌다.

## 설계: 2단 감시

좌석 단위 데이터는 비싸고, 잔여석 카운트는 싸다. 그래서 두 층으로 나눈다.

```
1단  회차별 잔여석 카운트를 주기적으로 폴링
     └ 수가 늘어난 회차 = 취소표 발생 → 2단으로
2단  그 회차만 좌석맵을 1회 조회
     └ 좌석 블록 · 단석/연석 조건을 실제로 판정
```

폴링 1회당 요청 수 = **감시 지점 수**. 영화를 몇 편 걸든 늘지 않는다
(`GetPlaySequence` 가 영화 미지정으로 전 회차를 한 번에 준다).

## 실측으로 확정한 것 — 2026-08-09 롯데시네마 월드타워 9관

전부 실제 예매 화면의 DevTools 캡처와 API 응답 대조로 확인했다. 추측한 값은 없다.

### 1. `BookingSeatCount` 는 이름과 반대로 **잔여석**이다

```
19:10 div100  Total 342  Booking   7   → 사이트 표기 "6 / 342"
22:40 div100  Total 342  Booking 215   → 30분 전 사이트 "237 / 342"
19:10 div960  Total  18  Booking   0   → 프라임타임 리클라이너 매진
```

`Total - Booking` 으로 계산하면 매진 직전인 회차가 "335석 여유"로 보인다.
결정적 근거는 리클라이너다 — "예매된 수"라면 프라임타임에 0석 팔렸다는 뜻이 된다.

`test/parse.test.ts` 가 이 반전을 회귀 테스트로 잠가 두었다.

### 2. `cinemaID` 앞 두 조각은 지점 속성이 아니라 조회 축이다

```
1|0001|1016  → 40 showtimes   (지역 탭: 서울)
2|0960|1016  →  0 showtimes   (지점 객체의 DivisionCode)
```

`GetTicketingPageTOBE` 응답의 지점에 붙어 있는 `DivisionCode|DetailDivisionCode`
를 그대로 쓰면 서버가 **에러 없이 빈 배열**을 준다. `daiso`(k-skill 의
`korean-cinema-search` 가 경유하는 CLI)가 정확히 이 지점에서 틀려서
월드타워 40개 회차 중 0개를 반환했다.

### 3. 좌석 상태는 `SeatStatusCode` 로만 판단한다

```
  0 →   6   판매 가능        ← 사이트 "6석 남음" 과 일치
 50 → 335   예매 완료
 28 →  13 ┐
 80 →   3 │  비어 있지만 팔지 않는 좌석 19석
 23 →   2 │  (장애인석 · 거리두기 등)
 20 →   1 ┘
           합 360 · BookingSeats 354 = 360 - 6
```

`blocked` 를 `free` 에 섞으면 잡을 수 없는 자리에 알림이 간다.

### 4. 통로는 `SeatColumGroupNo` 가 직접 알려준다

```
H04→H05  gap 583  group 1→2
H08→H09  gap 583  group 2→3
H22→H23  gap 583  group 3→4
정상 간격 283
```

좌표 추정 없이 구획 번호로 확정할 수 있고, x 간격은 교차 검증용으로 쓴다.
번호가 연속이어도 통로 건너면 연석이 아니다 — `test/runs.test.ts` 의 첫 테스트가
이 함정을 지킨다.

임계값은 **행마다** 잡는다. 같은 관의 리클라이너 행은 정상 간격이 470 이라
일반석 통로 폭(583)에 가깝고, 전체 중앙값으로 재면 멀쩡한 연석이 끊긴다.

### 5. 파라미터 이름 함정

```
GetPlaySequence : cinemaID (대문자 D) — "1|0001|1016" 문자열
GetSeats        : cinemaId (소문자 d) — 1016 숫자
```

헷갈리면 에러 없이 빈 응답만 온다. `screenDivisionCode` 는 필터가 아니라서
100 을 보내도 리클라이너까지 전 좌석이 온다.

## 픽스처

`test/fixtures/lotte-worldtower-9gwan-seq4.json` 은 위 계약을 그대로 재현한
합성 데이터다(`npm run fixture` 로 재생성). 좌석 수·구획 히스토그램·상태
히스토그램이 실측과 일치하고, 판정을 시험하는 배치를 심어 두었다.

```
H04 / H05   번호는 연속이지만 통로를 사이에 둔 함정 — 연석 아님
J10 / J11   진짜 2연석
C15 / N20   단석
```

실제 캡처본이 있으면 같은 디렉터리에 두고 동일한 테스트를 돌리면 된다.
롯데가 API 를 바꾸면 감시 루프가 조용히 틀린 답을 내기 전에 테스트가 먼저 깨진다.

## 지켜야 할 선

1. **동시 홀드 1건.** 여러 회차를 동시에 잡아두지 않는다
2. **미결제 즉시 해제.** 만료를 기다리지 않는다
3. **재시도 상한.** 같은 회차 3회, 감시 만료시각 필수
4. **폴링 하한 30초.** k-skill `catchtable-sniper` 규약과 동일
5. **결제는 사람.** 카드 정보 자동 입력·자동 결제 없음

캡차나 대기열이 나오면 우회하지 않고 중단한다.
